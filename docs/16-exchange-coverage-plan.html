Exchange coverage: what we see, what we trade

This page checks whether Ownback's market data, simulations and swaps take every Solana exchange into account. It then sets out the fix: one pool list per token, totals summed across exchanges, and a per-exchange quote and swap the user can pick. This comes before any other new feature.

1 · Audit

The three parts, checked live today

Covers all exchanges

Swaps

Built by Jupiter's router, which reaches 112 Solana exchanges and can split one order across several. No quote setting restricts it: no onlyDirectRoutes, dexes or maxAccounts.

Covers all exchanges

Simulation (token count)

The buy review's figure comes from the same Jupiter quote that builds the swap, so it is the best across all exchanges. But it only shows one number, with no breakdown by exchange.

Does not

Market data

Liquidity and volume come from Jupiter's token summary, which is undercounted or computed differently. Charts come from one pool only. No screen lists the exchanges a token trades on.

What this means

  • Prices and swaps are already best-of-all-exchanges. A different exchange that showed bigger liquidity or volume doesn't give a better price, because Jupiter is already trading against that pool.
  • What the app shows is wrong or incomplete. Liquidity is understated by up to 39% (TSLAx), charts use one pool, and the user can't see or choose exchanges. That is the real bug.
  • Ondo tokens have almost no Solana market at all. No exchange on Solana fixes that. They stay listed with a clear "Thin market" warning; their deeper markets are on other chains (later phase, docs/15 P4).
2 · The fix

One pool list per token, used everywhere

A small server-side pool index becomes the one source for "where does this token trade". Market data is summed from it, and the per-exchange quotes are built from it. The swap itself keeps today's Jupiter connection, safety checks and fee; picking an exchange only narrows which pools Jupiter may use.

F1

Pool index

lib/markets/pools.ts fetches every pool per mint from DexScreener (/token-pairs/v1/solana/:mint, free, 300 calls/min). GeckoTerminal stays as a fallback.

  • Keep pools quoted in USDC, USDT or SOL with at least $1,000 liquidity. Meme pairs and dust pools are dropped from totals and from the exchange list.
  • Group them by exchange: raydium, orca, meteora, pumpswap, pancakeswap, fluxbeam, and so on. A fixed map turns each one into Jupiter's labels: Raydium → Raydium,Raydium CLMM,Raydium CP; Orca → Whirlpool; Meteora → Meteora DLMM,Meteora DAMM v2,Meteora; PumpSwap → Pump.fun Amm.
  • Store one row per pool: migration 0012 changes market_pools to key on (mint, pool). Cached for 10 minutes and warmed by the markets worker for the top assets.
F2

Market data from all exchanges

  • Liquidity is the sum of the kept pools. Volume 24h is the sum of the kept pools, with Jupiter's routed volume shown on the detail page as a second line.
  • Price stays Jupiter's (an executable, cross-exchange price). Each exchange row shows its own pool price.
  • Chart uses the deepest USDC pool, labelled "Chart: Raydium CLMM pool" so it's clear which one.
  • Used by Markets, the asset page, the receipt token list and the buy review stats (token-stats.ts and buyable.ts read the index instead of Jupiter's token summary).
F3

Per-exchange simulation

  • For each token, quote "Best price" (Jupiter over all exchanges, which may split) plus each exchange in the index with at least $10k liquidity, at most four. Each extra quote uses Jupiter's dexes= filter, the same platformFeeBps and the same slippage, so token counts are exact and include the fee.
  • Each row shows tokens you get, average price, price impact, cost against the share price, pool liquidity and volume.
  • Speed: the review shows "Best price" straight away, as today. The exchange quotes load when the user opens "Compare exchanges", in parallel within a 1.5-second budget, and a slow one says "No quote right now". Cached for 15 seconds per token and amount.
F4

Swap on the chosen exchange

  • POST /buys and POST /sells take an optional exchanges: {assetId: exchangeKey}. The server checks it against the exchanges offered in that quote and rejects anything else (exchange_not_offered).
  • buildUserSwap passes dexes to the quote it builds from. Every existing check stays: the relay pays, the user is the only other signer, tokens land in the user's own account, and the fee only applies to buys.
  • If the chosen exchange can't fill within slippage at signing time, return ROUTE_CHANGED with the new best. The app shows the "Route changed" sheet; there is never a silent switch.
  • buy_entries.venue (already exists, NOT NULL) records jupiter or jupiter:raydium, and sells gets the same column, so history shows where each trade went.
F5

Honesty on thin tokens

  • A token with under $10k total liquidity gets a Thin market tag in every list.
  • An exchange row whose price is more than 5% off the best gets a warning.
  • The registry field venues: ["jupiter"] becomes the list of exchanges from the index (display only; it never gates a buy).
Not changing: the Jupiter connection, D43 tradability (live $5 quote within 5%), D44 fee, D46 company jars and token choice, and docs/15's DFlow and market-maker phases, which stay after this. This page replaces docs/15's P1 "Compare routes" with "Compare exchanges".

Wireframes

4 · Order of work

Commits, each one shippable

  1. Pool index and migration 0012, with a test on recorded DexScreener data (filters, grouping, label map). No screen change.
  2. Market data from the index: markets, asset page Exchanges table, receipt list, review stats, Thin market tag.
  3. Per-exchange quotes (GET /api/quotes/exchanges?assetId&amountUsd6) and the Compare exchanges sheet, display only.
  4. Swap on the chosen exchange: the exchanges field, dexes in the swap, ROUTE_CHANGED, venue recorded on buys and sells. A $1 live buy on each of Raydium and Orca before release.
  5. Docs: D47 in docs/03, api-contract, copy-and-errors, and docs/15 P1 pointing here.

Needs from you

  • A Jupiter API key is strongly advised before step 3. Comparing four exchanges is five quotes per token, and the keyless API allows about one per second. Without a key, step 3 ships with Compare limited to two exchanges.
  • Nothing else: DexScreener needs no key.

Still open

  • Which exchanges you found with better liquidity. If it was a token or chain other than these, send the link and I'll add it to Evidence A.
  • DexScreener's free API has no service guarantee. GeckoTerminal is the fallback; a paid feed (Birdeye or CoinGecko Pro) is an option if both fail often.
